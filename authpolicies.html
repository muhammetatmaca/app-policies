Clause 01.0 / Architecture Air-Gapped Doctrine

The Zero-Knowledge Imperative & Fundamental Philosophy

Mathematical proof of non-possession: Why we can never access, leak, subpoena, or analyze your two-factor tokens.

Modern digital security relies heavily on multi-factor authentication (MFA). However, the mainstream industry has introduced severe vulnerability vectors by forcing authenticators into centralized cloud ecosystems. Cloud-synced 2FA services create centralized honey pots vulnerable to server compromise, database breaches, SIM-swapping cascade attacks, and rogue internal access.

Nova Authenticator 2FA was architected with a singular mathematical axiom: what is never collected can never be leaked, stolen, coerced, or compromised. We operate under the cryptographic principle of Zero-Knowledge by Construction. The application functions as an autonomous, self-contained mathematical engine.

Mathematical Guarantee of Non-Possession
Nova Authenticator 2FA has zero user databases, zero user registration, zero cookies, zero IP logging, and zero telemetry. Even under court order, state-level subpoena, or hostile infrastructure inspection, it is physically and architecturally impossible for us to provide token data because no server exists to receive, index, or decrypt it.

Clause 02.0 / Cryptography RFC Standards

Cryptographic Architecture & RFC Specifications

Complete transparency regarding cryptographic hashing algorithms, time-synchronization mechanics, and entropy sources.

Nova Authenticator 2FA implements the Internet Engineering Task Force (IETF) open cryptographic specifications: RFC 6238 (Time-Based One-Time Password Algorithm - TOTP) and RFC 4226 (HMAC-Based One-Time Password Algorithm - HOTP).

2.1 The TOTP Computation Pipeline

The generation of one-time passcodes occurs entirely within local volatile RAM and adheres to the following cryptographic formula:

RFC 6238 TOTP ALGORITHMIC SPECIFICATION 
// Step 1: Unix Timestamp to Discrete Time-Step Counter T
T = floor((CurrentUnixTime() - T0) / X)
Where T0 = 0 (Unix Epoch) and X = TimeStepPeriod (Standard: 30 seconds)

// Step 2: HMAC-Hash Computation over Big-Endian 64-bit Counter T
HMAC_Hash = HMAC-SHA-x(Base32_Decode(SecretKey), Int64ToBytes(T))
Supported Hash Functions: SHA-1 (RFC Standard), SHA-256, SHA-512

// Step 3: Dynamic Truncation (DT) extraction of 31-bit integer
Offset = HMAC_Hash[Length - 1] & 0x0F
BinaryCode = ((HMAC_Hash[Offset] & 0x7F) << 24) |
             ((HMAC_Hash[Offset + 1] & 0xFF) << 16) |
             ((HMAC_Hash[Offset + 2] & 0xFF) << 8)  |
             (HMAC_Hash[Offset + 3] & 0xFF)

// Step 4: Modulo Reduction to Desired Digit Length
TOTP_Code = BinaryCode % (10 ^ Digits)  // Digits standard: 6 or 8

Clause 03.0 / Hardware Secure Enclave

Hardware Enclave & Local Keystore Isolation

Protection against rooting, jailbreaking, physical memory dumps, and hostile application inspection.

Unlike standard mobile applications that store secrets in unencrypted shared preferences or cleartext databases, Nova Authenticator 2FA binds its master encryption credentials directly to the host platform’s hardware security module (HSM):

  • On Android: The AndroidKeyStore provider is leveraged via hardware-backed Keymaster / Keymint running inside a Trusted Execution Environment (TEE) or dedicated StrongBox Keymaster chip.
  • On iOS: Secrets are protected by the Apple Secure Enclave processor (SEP) with kSecAccessControlBiometryAny access control policies.
Hardware Security Enclave Architecture Isolation Level: Level 3+

3.1 Protection Against Memory Dumping & Cold-Boot Attacks

When one-time passcodes are calculated, plaintext secrets reside in allocated heap memory for only microseconds. Immediately following calculation, the application invokes explicit zero-fill byte scrubbing routines to overwrite buffer memory with 0x00 null bytes, preventing forensic extraction from OS swap files or RAM dumps.

Clause 05.0 / Permissions Hardware Audit

Device Permissions & Hardware Access Policy

A line-by-line audit of OS permissions, explaining their technical purpose, isolation boundaries, and security controls.

Nova Authenticator 2FA requests only the absolute minimum permissions strictly essential for user functionality. Each requested permission is isolated behind strict runtime user consent:

5.1 Camera Permission (android.permission.CAMERA / NSCameraUsageDescription)

Purpose: Used exclusively to scan optical two-factor QR barcodes formatted in the standard otpauth:// URI format.

Zero-Storage Camera Processing
Camera image frames are scanned directly in memory by on-device barcode recognition shaders. No photographs, video frames, or metadata are ever saved to disk, recorded, cached, or transmitted. As soon as a valid QR code is recognized, the camera stream is instantly terminated and released.

5.2 Biometric Hardware Access (USE_BIOMETRIC / NSFaceIDUsageDescription)

Purpose: Optional vault authentication via FaceID, TouchID, or Android BiometricPrompt.

Biometric templates (fingerprint vectors or facial depth maps) never leave the device’s physical Secure Enclave. Nova Authenticator 2FA does not have access to your biometric data; it receives only a cryptographic challenge response (BiometricPrompt.CryptoObject) signed by the operating system kernel.

5.3 Absence of Network Permissions

Unlike 99% of modern apps, Nova Authenticator 2FA does not include background synchronization services. The app operates with full integrity even when placed inside a Faraday bag or with Airplane Mode enabled.

Clause 10.0 / Deletion Cryptographic Shredding

Data Retention & Cryptographic Shredding Policy

How accounts are permanently obliterated upon uninstallation or manual vault clearance.

Nova Authenticator 2FA provides an irreversible self-destruction feature labeled “Erase All Accounts” within the Settings modal. When triggered:

  1. The local SQLite / AsyncStorage vault payload is overwritten with cryptographically random garbage before unlinking.
  2. The OS Keystore master key reference is permanently deleted from the hardware security enclave.
  3. Volatile RAM token state is wiped with zeroes.
  4. Uninstalling the application causes the mobile OS sandboxing system to completely delete all application directories.
Irreversible Deletion Notice
Because Nova Authenticator 2FA possesses zero cloud backups, deleted accounts CANNOT be recovered by our team. Always maintain an offline, encrypted Aegis JSON export or printed paper emergency backup codes.
